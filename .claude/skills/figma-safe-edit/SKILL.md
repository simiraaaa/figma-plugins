# Figma を安全に書き換える

Local Bridge の /run で Figma を書き換えるときに従う。
Local Bridge 自体の使い方は `<リポ>/plugins/local-bridge/README.md` にある。

- `<リポ>`: この SKILL.md のパスから `.claude/skills/figma-safe-edit/SKILL.md` を除いたディレクトリ。
- `<URL>`: Local Bridge の画面からコピーした文にある dev サーバー (例: `http://localhost:47717`)。
- `<合言葉>`: 同じ文にある `X-Run-Token` の値。
  合言葉はそのファイル専用で、別のファイル宛ての script に付けても実行されない。
  これは行き先の取り違えを止めるためのもの。照合を通った script は別のファイルの合言葉 (`figma.clientStorage`) を読み書きできるので、それをしない。
- `<fileKey>`: 行き先のファイルの fileKey。
  同じ文の「行き先のファイル」にある。
  人から Figma のファイルのリンク (`https://www.figma.com/design/<fileKey>/<ファイル名>?...`) を渡されたら、その `<fileKey>` の部分を使ってよい。
  ただし、リンクに `/branch/` が入っているときはキーを取り出さず、どの fileKey に送るかを人に聞く (ブランチのファイルの fileKey がリンクのどちらのキーになるかは確かめていない)。
  リンクだけでは合言葉が無いので、書き換えるなら、そのファイルのタブで「AI に渡す文をコピー」した文を貼ってもらう。

script も書き出しも、いつも `?file=<fileKey>` を付けて送る (詳しくは README の「script の実行」と「複数のファイルで開く」)。
Local Bridge は複数のファイルで同時に開いていることがあり、`file` が行き先を決める。

```sh
curl -s -X POST '<URL>/run?file=<fileKey>' -H 'X-Run-Token: <合言葉>' --data-binary @<script のファイル>
```

HTTP 400 (`file` が無い) か 503 (そのファイルで Local Bridge が繋がっていない) が返ったら、本文の `plugin` に Local Bridge が繋がっているファイルの一覧 (`fileName` と `fileKey`) が入っている。
一覧を人に見せ、どのファイルに送るか (またはそのファイルで Local Bridge を開くか) を聞く。
一覧から自分で選んで送らない。
一覧が 1 件だけでも、名前が似ていても同じ。
合言葉はファイルごとなので、一覧の別のファイルに `?file=` を差し替えて送り直しても、その script は実行されない (取り違えの事故を止めるため。差し替えて送らない)。
人が別のファイルを選んだら、そのファイルのタブでコピーした渡す文を貼ってもらう。

## 始める前に

- 書き換えるファイルの名前と、行き先の `<fileKey>` を確かめる。
  渡す文の「行き先のファイル」の名前か、人から渡されたリンクのファイルが、頼まれたファイルかを人に確かめる。
- 同じファイルを分割表示や別のタブで 2 つ開いていても、依頼を受けるのは先に Local Bridge を開いた画面だけ (あとから開いたほうは断られて止まる)。
  人に Cmd+Z・Cmd+Shift+Z を頼むときは、依頼を受けている画面で押してもらう (取り消しの履歴は画面ごと)。
- `return figma.root.name;` を `?file=<fileKey>` を付けて送り、確かめた名前が返ることを確かめる。
  違う名前が返ったら、書き換えずに人に伝える。
- 4 で戻し終えるまで (戻さないなら 3 で確かめ終えるまで)、同じファイルを手で書き換えないよう人に頼む。
  人が手で書き換えると、戻すときにそちらが先に戻る。
  戻す前の確かめはスナップショットに映るものしか見ないので、映らない値 (書き出し設定・プラグインのデータなど) を触られても気づけない。
  見るだけ (ページの移動・選択。report の「Figma で開く」で飛ぶことを含む) は構わない (4 の取り消しは移動の手を先に戻してから書き換えの手を戻す)。

## 1. 書き換える前を書き出す

書き換えるノードをすべて含む、いちばん小さいノードの id を決める。
ノードを足す・消すなら、その親にする。
離れた場所のノードを書き換えるなら、それぞれの id を `nodeIds` に並べてよい。

```sh
curl -s -X POST '<URL>/export?file=<fileKey>&timeout=110' -d '{"nodeIds":["<id>"]}'
```

応答の `dir` を before として控える。
大きいノードで時間が掛かるときの待ち方は、README の「使い方」の 3 にある。

続けて、ファイル全体のスナップショット (全ノードの要約。`scripts/fingerprint.js`) を取り、保存する (書き出した範囲の外を script が変えていないかを 3 で確かめるため)。
1 万ノードのファイルで数秒。
返り値の大きさ (1 ノードあたりの文字数と、上限の 100 万文字に届くノード数) の実測は README の「書き出した範囲の外の変化を見つける」にある。
保存先は書き出しの置き場所 (`GET /status` の `outDir`) の下の `fingerprint/` で、無ければ作る。

```sh
mkdir -p <書き出しの置き場所>/fingerprint
curl -s -X POST '<URL>/run?file=<fileKey>&timeout=580' -H 'X-Run-Token: <合言葉>' --data-binary @<リポ>/scripts/fingerprint.js > <書き出しの置き場所>/fingerprint/<seq>.json
```

`error` が返ったら (ノードが多すぎて返り値が上限を超えた、など)、スナップショットなしで進み、範囲の外は確かめられないことを人に伝える。
書き出せなかったとき (HTTP 422・503・504) は、書き換えに進まない。
README の「使い方」に従って書き出し直す。

書き出しに映らないものがある。
次のものを書き換えるときは、それぞれの確かめ方を使う。

- 非表示のノード (とその子): 書き出しに出ない (コンポーネントのプロパティで出し入れする子は、非表示でも構造の差分に出る)。
  書き換える前の値と後の値を、script の返り値で返して確かめる (3 と 4 でも、書き出しを比べる代わりにこの値を使う)。
  書き換えるノード自体が非表示なら、そのノードは書き出せない (HTTP 422)。
  書き出しには表示されている親を使う。
- セクションの直下にある、フレーム・インスタンス・コンポーネント・グループ以外のノード (文字・図形・コンポーネントセットなど): 構造の差分は出るが、画像は出ない。
  画像も見たいなら、セクションでなくそのノードを書き出す。
- メインコンポーネント・スタイル・変数: 使っている別の場所 (インスタンス・ほかのページ) も変わる。
  変わる先も `nodeIds` に入れ、画像の差分で見られるようにする (3 の全体スナップショットは id しか出さない)。
  メインコンポーネントなら、下の script でインスタンスを含むページ直下 (セクションの中ならセクション直下) のフレームを探す (`<id>` はコンポーネントかコンポーネントセットの id)。
  返った id を `nodeIds` に足す。
  多いとき (目安 20 を超える) は、ページごとに 1 つずつなど代表を選び、残りは確かめられないことを人に伝える。
  スタイル・変数は使っている場所を Plugin API で探せないので、人に聞くか、確かめられない範囲があることを伝える。

  ```js
  const target = await figma.getNodeByIdAsync("<id>");
  const mains = new Set(target.type === "COMPONENT_SET" ? target.children.map((c) => c.id) : [target.id]);
  await figma.loadAllPagesAsync();
  const tops = new Map();
  for (const page of figma.root.children) {
    for (const instance of page.findAllWithCriteria({ types: ["INSTANCE"] })) {
      const main = await instance.getMainComponentAsync();
      if (!main || !mains.has(main.id)) continue;
      let top = instance;
      while (top.parent && top.parent.type !== "PAGE" && top.parent.type !== "SECTION") top = top.parent;
      tops.set(top.id, page.name + " / " + top.name);
    }
  }
  return [...tops].map(([id, name]) => id + " " + name);
  ```

## 2. 書き換える

script は次の形にする。

```js
if (figma.root.name !== "<ファイル名>") throw new Error("別のファイル: " + figma.root.name);
figma.commitUndo();
try {
  figma.root.setPluginData("ai-edit", "<印>");
  // ここで書き換える
} finally {
  figma.commitUndo();
}
figma.notify("AI の書き換えが終わった: <何をしたか>", { timeout: 10000 });
return "<確かめたい値>";
```

- 頭と終わりの `figma.commitUndo()` で、この script の書き換えが取り消しの 1 手になる。
  無いと、前に送った script の書き換えと 1 手にまとまり、戻すときに一緒に戻る。
  終わりの `commitUndo()` を `finally` に置くのは、途中で例外を投げても書きかけの変更を 1 手に区切るため。
- `setPluginData` の行はこの 1 手の印。
  `<印>` には 1 の before の `seq` を入れる (書き換えごとに違う値にする。前の書き換えの印が残っていても、値が違えば見分けられる)。
  印は同じ 1 手に入るので、4 では「印が消えた = この 1 手まで戻した」と見る (2026-10-27 に実測)。
  印は書き出しにもスナップショットにも映らない。
  書き換えより先に書くのは、途中で例外を投げた書きかけの 1 手にも印を残すため。
- 終わりの `figma.notify()` で、Figma の画面に書き換えが終わったことを出す。
  人は Figma を見ていて AI の端末を見ていないので、Figma の画面で分かるようにする。
  `finally` の外に置き、途中で例外を投げたときは出さない (終わっていないため)。
  既定の表示は短くて見逃すので (2026-10-28 に人が見逃した)、`timeout` を 10 秒にする。
- 書き換えは 1 つの script にまとめる。
  2 つ以上に分けるなら、script ごとに 1〜3 を回す。
- `await` で待つ処理 (フォントの読み込みなど) は、書き換えより前に済ませる。
  待つあいだに人が触って起きた変化が、この script の 1 手に混ざるかもしれない (未確認)。
- 成功 (HTTP 200) 以外が返ったとき (応答が返らないまま curl が止まったときを含む) は、script が Figma で動いたかを README の「script の実行」で見分ける。
  504 は、README のとおり `/status?seq=<seq>` で決着を待ってから見分ける (`done` は成功と同じに扱い、`failed` は `error` の文を 422 と同じに読む)。
  - 動いていないと分かったとき (HTTP 400・503・422 の「実行していない」・504 の「プラグインに渡せなかったので取り消した」・`cancelled`・`skipped`): Figma は変わっていない。
    直して送り直す (400・503 なら、上のとおり一覧を人に見せて行き先を聞くか、人にそのファイルで Local Bridge を開いてもらってから)。
  - それ以外のとき: どこまで書き換えたか、取り消しの 1 手ができたかが分からない。
    送り直さず、取り消しも送らない。
    3 で後を書き出して比べ、比べた結果を人に伝えて、戻すかどうかは人に決めてもらう。
    人が戻すと決めたら、「<ファイル名> の、Local Bridge が依頼を受けている画面を前に出してから、<書き換えた所> が元に戻るまで Cmd+Z を押して、押した回数を教えて」と、ファイルの名前を入れて頼む (Cmd+Z は前に出ている画面のファイルに効き、取り消しの履歴は画面ごとにあるので、別のファイルや別の画面が前にあると、別の手が戻る。report のリンクで飛んだ分も 1 回 1 手で先に戻るので、1 回とは限らない)。
    押してもらったら 4 の 3 で確かめる。

## 3. 後を書き出して比べる

1 と同じ curl で書き出し、応答の `dir` を after として控える。
1 でスナップショットを取っていれば、もう一度取って、前後の 2 つを `compare` に渡す (書き出した範囲の外の変化も一緒に出る)。

```sh
curl -s -X POST '<URL>/run?file=<fileKey>&timeout=580' -H 'X-Run-Token: <合言葉>' --data-binary @<リポ>/scripts/fingerprint.js > <書き出しの置き場所>/fingerprint/<seq>.json
npm --prefix <リポ> run -s compare -- <before> <after> --fingerprint-before <前のスナップショット> --fingerprint-after <後のスナップショット>
```

出力の JSON の欄は次のとおり。

- `same`: 変わったところが無ければ `true`
- `changed`・`added`・`removed`: 変わった・足された・消えたファイル
- `renamed`: 名前が変わったノードのファイル (ノード ID で前後を組にしてある)
- `images`: 画面の画像ごとの、色が違う画素の数と、変わった箇所の範囲 (`regions`。離れた変化ごとに分けてある。変わった所が多すぎるときは 1 つにまとめる)
- `changesDiff`: 構造の差分 (`diff -u`) を書いたファイル。
  差分の区切りの行 (`@@`) の後ろに、変わった箇所の直前に始まるノードの ID が出る (子を消した箇所では、直前の兄弟などを指すことがある)。
- `sameChanges`: 構造の差分のうち、同じ中身の変化が 2 箇所以上あるもの (多い順。箇所の数・足した行と消した行・どのノードか)
- `report`: 人が見る HTML。
  先頭に AI の見立て (`--note` を渡したとき) と、書き出した範囲の外の変化 (下の `fingerprint` の `outside` と `propagated`) を、範囲の外 → インスタンスに映ったものの順で出す (`inside` は意図した変化なので載せない)。
  続けて、変わった箇所を 1 つずつ切り出した before・after・差分 (色が違う画素を赤くしたもの) の画像 (範囲が広い箇所と 31 箇所目からは、全体の画像で見る) と、どこが変わったかを枠で示した全体図を並べる。
  構造の差分は同じ中身の変化をまとめて箇所の数を出し、ファイルごとに畳んで並べる。
  画像とノードには「Figma で開く」のリンクが付き、押すと Figma デスクトップがそのノードを選択して前に出る。
- `fileKey`: 書き出した Figma のファイル。Local Bridge の書き出しでなければ `null` で、report にリンクは付かない。
- `fingerprint`: ファイル全体の比較 (下の `inside`・`propagated`・`outside`)。スナップショットを渡していなければ `null`。
  `same` は書き出しだけを見るので、書き出しに映らないノード (非表示の子など) の変化は `same: true` のまま `inside` に出る。
  書き出した範囲は after の `index.json` の根 (1 の `nodeIds` のうち表示されているもの。ページを書き出したならそのページ)。
  同じ名前のページが 2 つ以上あって決められないときは、`--inside <id>[,<id>...]` で 1 の `nodeIds` を渡す。
  スナップショットの `fileKey` が書き出しの `fileKey` と違えば、取り違えなので断る。
- `note`: `--note` で渡した見立ての文 (渡していなければ `null`)。

書き出しの応答に `warnings` があれば、比べた結果を使う前に見る。
画面がスリープしているあいだの書き出しは、警告つきで画像が欠けることがある。
普段は出ない警告があれば、人に画面を起こしてもらい、書き出し直して比べ直す。

`fingerprint` の 3 つの欄で、書き出した範囲の外の変化を見る。
書き出しなしでスナップショットだけを比べるときは `npm --prefix <リポ> run -s fingerprint -- diff <前> <後> --inside <id>[,<id>...]` (同じ 3 つの欄を出す)。

- `inside`: 範囲の中で変わったノード。書き出しの比較と同じものを指すはず。
- `propagated`: 範囲の中のノードがメインコンポーネントの中にあり、その変化がインスタンスに映ったもの (`from` が元のノード)。
  範囲の外にあるが、範囲の中の書き換えの結果。
  映った先の数とページを人に伝え、そのコンポーネントを変えてよかったかを確かめる (2026-10-28 の実測では、Button の中のレイヤー名 1 つで 4 ページ 42 個のインスタンスが変わった)。
  元のノードが変わっていれば、そのインスタンスの中のノードの変化は全部ここに入る。
  script がそのインスタンスも直接書き換えていた場合は、映ったものと区別できない。
  だから `propagated` を自動で「問題なし」にはしない (`diff` の終了コードも 0 にならない)。
  script が触った id を自分で照らし、触っていなければ映っただけと見て、数とページを人に伝える。
- `outside`: それ以外の、範囲の外の変化 (`moved` は、中身は同じでも親やページが変わったノード。`document` はページの並び)。
  空でなければ、script が意図しない場所を変えているか、意図した書き換えの影響が範囲の外に及んでいる。
  後者の例は、インスタンスが広がって同じ自動レイアウトの隣のノードの位置が変わること (2026-10-28 の実測では、Button のメインコンポーネントに子を 1 つ足すと、`propagated` 84 件のほかに隣のノードが 14 件 `outside` に出た)。
  どちらかは id を見て自分で分け、両方とも人に伝える。
  script のミスと分かったものは 4 に進む (2 で成功以外が返っていれば、分けた結果を人に伝える)。
- `aspects`: `changed` のノードで変わった区分 (`name` 名前・`geometry` 位置と大きさ・`look` 見た目・`text` 文字・`layout` 自動レイアウトの設定・`component` 種類と property・`children` 子の並び)。
  見立ての手がかりにする。

`outside` が空でないときと、`propagated` に script が触った id が混ざるときは、id を並べただけでは人に意味が伝わらないので、見立てを書いて report の先頭に載せる。

1. 変わったノードを script で読む (`<id>` は `outside` の id。多ければ代表を選ぶ)。

   ```js
   await figma.loadAllPagesAsync();
   const out = [];
   for (const id of ["<id>", "<id>"]) {
     const node = await figma.getNodeByIdAsync(id);
     if (!node) { out.push(id + " (無い)"); continue; }
     const chain = [];
     for (let p = node.parent; p && p.type !== "DOCUMENT"; p = p.parent) {
       chain.unshift(p.name + ("layoutMode" in p && p.layoutMode !== "NONE" ? " [" + p.layoutMode + "]" : ""));
     }
     out.push(id + " " + node.type + " " + node.name + " @ " + chain.join(" / ") + " x=" + node.x + " y=" + node.y + " w=" + node.width + " h=" + node.height);
   }
   return out;
   ```

2. 同じ原因のまとまりごとに分けて書く。
   原因は script が触った id との関係 (触ったノードの自動レイアウトの兄弟か・そのインスタンスか) と `aspects` から決める。
   決められないものは「説明がつかない」にし、他の人の変更の疑いとして書く (自分のものと決めない)。
   型は次のとおり (空行で段落、行の頭の `- ` で箇条書き。HTML は書けない)。

   ```
   想定外の変化は <件数> ノード (<まとまりの数> 種類)。

   - <ページ> / <親> の <名前> ×<件数>: <変わった区分 (位置など)>。原因: <何がどうなったから>。<うちらの書き換えの影響 | script のミス | 説明がつかない (他の人の変更かも)>

   結論: <戻す | 戻さない | 人に確かめる> (<理由>)。
   ```

3. 見立てを書いたファイルを書き出しの置き場所の下の `note/<seq>.md` に置き (比べた結果の置き場所の中には置かない。やり直すと消える)、`compare` に `--note <そのファイル>` を足してやり直す。
   見立てを書き直したら、また `compare` をやり直す。
4. report を人に見せ、結論を伝える。
   「script のミス」があれば、この手順書の 4 (問題があれば戻す) に進む。
   「説明がつかない」があれば、4 に進まず人に確かめる。

複製したファイルで実測した (2026-10-28): ページの並べ替えは `document`、範囲の外の文字の配置だけの変更はその TEXT、メインコンポーネントへの子の追加は本体とインスタンスが、それぞれ `outside`・`propagated` に出た。

スナップショットに入る値は `scripts/fingerprint.js` の冒頭に書いてある (種類・名前・表示・位置・大きさ・塗り・線・効果・制約・レイアウト・文字の範囲ごとの書式・スタイル・コンポーネントの property・子の並びなど)。
見ていない値の変化は拾えない。

before と after が `same: true` のときは、script の返り値で値が変わったかを見る。

- 返り値でも変わっていない: script はノードを変えていない。
  ただし印を書いた分で、印だけの取り消しの 1 手はできている (印だけの区切りも 1 手になる。2026-10-27 に実測)。
  残すと、人が次に押す Cmd+Z がその空の手を戻して見た目が変わらず、戸惑わせるので、4 で印の手を戻す (4 の script は印に着いたら止まるので、前からある別の手は戻らない)。
- 返り値では変わっている: 書き出しに映らないもの (非表示のノードなど) を書き換えた。
  取り消しの 1 手はできている。
  確かめには返り値を使い、戻すなら 4 に進む。
- 返り値が無い (2 で成功以外が返った): 2 のとおり、取り消さずに人に伝える。

`changesDiff` を読み、変化を 3 つに分ける。
差分が長いとき (元のコンポーネントを変えて、使っている場所がまとめて変わったときなど) は、先に `sameChanges` で同じ変化をまとめて分け、残りを `changesDiff` で読む。
2 で成功以外が返ったときは、下で「4 に進む」に当たる変化があっても 4 には進まず、分けた結果を人に伝える。

- 意図した変化: 頼まれたとおりか確かめる。無いか違っていれば、問題として 4 に進む。
- 自分の script が起こした、意図していない変化: 問題として 4 に進む。
- 自分の script で説明できない変化: 同じファイルを別の人が編集していると、その人の変化も差分に出る。
  自分のものと決めず、4 にも進まずに、人に確かめる。

見た目の良し悪しは判定しない。
`open <report>` で report を開き、人に見て判断してもらう。

## 4. 問題があれば戻す

Figma の取り消し (Cmd+Z と同じ) で戻す。
値を書き戻す script は使わない。

Figma の取り消しの履歴には書き換えだけでなく、人のフォーカスの移動 (ページの移動・選択。`figma://` のリンクで飛んだものを含む) も 1 回ごとに 1 手として積まれる。
だから取り消しを 1 回だけ送っても、書き換えのあとに人が移動していれば移動が戻るだけで、書き換えは戻らない (2026-10-28 に起きた)。
下の手順 2 の script は、書き換えの script (2) で置いた印が消えるまで取り消しを繰り返す。
そのため、移動の手が上に積まれていても書き換えの 1 手まで戻り、印に着いたら止まるので、書き換えより前の手は戻さない (2026-10-29 に、リンクで 2 回飛んだあとに 3 回の取り消しで印に着き、飛ぶ前のページと選択に戻ったことを実測)。
script からのページの移動・選択・表示の変更は履歴に積まれない (同じ日に実測)。

1. 書き換えのあとに誰かが触っていないかを確かめる。
   スナップショットを取り直し、3 の after のスナップショットと比べる (書き出していないので、`--inside` に 1 の `nodeIds` を渡す)。

   ```sh
   curl -s -X POST '<URL>/run?file=<fileKey>&timeout=580' -H 'X-Run-Token: <合言葉>' --data-binary @<リポ>/scripts/fingerprint.js > <書き出しの置き場所>/fingerprint/<seq>.json
   npm --prefix <リポ> run -s fingerprint -- diff <after のスナップショット> <今のスナップショット> --inside <id>[,<id>...]
   ```

   `inside`・`propagated`・`outside` がどれも空なら、書き換えのあとに (スナップショットに映る範囲で) 誰も触っていない。
   どれかが空でなければ、書き換えのあとに誰かが触っている。
   取り消すとそちらが先に戻るので、取り消さずに人に伝える。
   書き換える前 (1) にスナップショットを取れなかったときは、代わりにもう一度書き出し、`compare -- <after> <その書き出し>` の `same` が `true` であることを確かめる (書き出した範囲の外は見られない)。
2. 印が消えるまで取り消しを送る (`?file=<fileKey>` を付ける。`triggerUndo` は、送ったファイルのタブの履歴に効く)。
   `<印>` は書き換えの script (2) で書いた値。
   `triggerUndo()` は同じ script の中で同期に効き、直後の `getPluginData()` に戻った値が映る (2026-10-29 に実測)。
   上限の 20 は、移動の手がそれより積まれることは無いと見た値 (人が report のリンクを押した回数より多ければよい)。

   ```js
   if (figma.root.name !== "<ファイル名>") throw new Error("別のファイル: " + figma.root.name);
   const LIMIT = 20;
   let count = 0;
   while (figma.root.getPluginData("ai-edit") === "<印>" && count < LIMIT) {
     figma.triggerUndo();
     count++;
   }
   return { undone: count, reached: figma.root.getPluginData("ai-edit") !== "<印>" };
   ```

   - `undone` が 0: 印が無い。
     書き換えの script (2) が印を書く前に止まったか、2 の型で書いていない (印だけの script でも、動いていれば印の 1 手ができている)。
     何も戻していないので、人に伝える。
   - `reached` が `false`: 上限まで取り消しても印に着かなかった。
     戻したのは移動の手のはずだが (書き換えは 1 で見ている)、これ以上は送らず、人に「<書き換えた所> が元に戻るまで Cmd+Z を押して」と頼み、押してもらったら 3 で確かめる。
   - 成功 (HTTP 200) 以外が返ったら、2 の書き換えと同じに見分ける。
     動いていないと分かったときだけ、直して 1 の確かめからやり直す。
     それ以外は、どこまで取り消したかが分からないので、もう送らない。
     3 で確かめた結果を人に伝える (Cmd+Shift+Z は頼まない。取り消していなければ、人が前に取り消した手がやり直される)。
3. もう一度書き出してスナップショットも取り、1 の before と比べる。

   ```sh
   npm --prefix <リポ> run -s compare -- <before> <reverted> --fingerprint-before <1 のスナップショット> --fingerprint-after <今のスナップショット>
   ```

   `same` が `true` で、`fingerprint` の `inside`・`propagated`・`outside` がどれも空なら、戻せた。
   書き換える前 (1) にスナップショットを取れなかったときは、`--fingerprint-before`・`--fingerprint-after` を付けずに比べ (`fingerprint` は `null` になる)、`same` が `true` なら戻せたと見て、書き出した範囲の外は確かめられないことを人に伝える。
   そうでなければ、3 のとおり、書き出しの `warnings` を見て、画像が欠けていないかを先に確かめる。
   欠けていなければ、印まで戻したのに書き換える前と違う。
   `triggerUndo` はもう送らず、変わったノードを 3 の見立てと同じ手で読み、「誰かの編集があるかも (書き換える前と後のあいだに、別の人が触っているか、スナップショットに映らない形で触られている)」として、変わったノードと一緒に人に伝える。

`triggerUndo` を 1 の確かめなしに送らない。
印の無い script (2 の型で書いていない書き換え) は、この手順では戻せない。
人に「<書き換えた所> が元に戻るまで Cmd+Z を押して」と頼み、戻ったら 3 で確かめる。

## 終わったら

比べた結果は書き出しの置き場所の下の `compare/` に残る。
人に report の場所を伝える。
