# Local Bridge 利用ガイド

Local Bridge を使うデザイナーや担当者が、最初に読む文書。
何ができるか、初めて使うときの準備、2 回目以降の使い方、困ったときの対処を、このページだけで追えるように書く。
細かい仕様は [README](README.md)、AI が Figma を書き換えるときの手順は [書き換えの手順](../../.claude/skills/figma-safe-edit/SKILL.md) にあり、AI はそれを読んで動く。
人がそれを読む必要はない。

## 何ができるか

Local Bridge は手元の Figma を AI (Claude Code など) に読み書きさせるためのプラグイン。

- 読む: 画面やコンポーネントの構造と画像を AI に読ませる (実装の参考にする・仕様を書き出す)。
- 調べる: 名前の揺れ・綴り違い・どこにもつながっていない property などを、AI にファイル全体から探させる。
- 書き換える: 組み合わせ表を並べる・名前や色をまとめて直す、など。レイヤーを消すこともできる。
  AI は書き換える前と後を書き出して比べ、結果 (report) を見せる。
  意図しない変化があれば、Figma の取り消し (Cmd+Z と同じ) で戻す。

Figma の公式 MCP と違って回数の上限が無いので、書き出して見比べる往復を何度でも回せる。
Figma のログインや MCP の認証は要らない。

## 用意するもの

- Figma デスクトップアプリ (開発中のプラグインを取り込めるのはデスクトップアプリだけ)。
  入っていなければ https://www.figma.com/downloads/ から入れる。
- Node 22.18 以上 (23 系なら 23.6 以上)。
  入っていなければ https://nodejs.org/ から入れる。
- git
- Claude Code など、手元でコマンドを実行できる AI。
  Claude Code は https://code.claude.com/docs/ja/overview から入れる。

下のコマンドは Claude Code に「このコマンドを実行して」と頼んでもよい。

## 初めて使うとき (1 回だけ)

1. リポジトリを clone する。
   置いた場所は Figma に取り込んだあと動かさない (Figma は取り込んだ場所のファイルを毎回読み直すので、動かすとプラグインが動かなくなる)。

   ```sh
   git clone https://github.com/simiraaaa/figma-plugins.git
   ```

2. clone したディレクトリで build する。

   ```sh
   npm install
   npm run build
   ```

3. Figma で、どれかのデザインファイルを開く。
   Dev Mode になっていたら、ツールバーの切り替え (Shift+D) で Dev Mode をオフにする (Local Bridge は Dev Mode では使えない)。
   **プラグイン** → **開発** → **マニフェストからプラグインをインポート…** を選び、clone したディレクトリの `plugins/local-bridge/manifest.json` を選ぶ。

取り込みは 1 回だけでよい。
以降はどのファイルでも **プラグイン** → **開発** → **Local Bridge** から起動できる。

## 使うたびに (2 回目以降も)

1. clone したディレクトリで dev サーバーを起動し、動かしたままにする。
   Claude Code に「dev サーバーを background で起動して」と頼んでもよい。

   ```sh
   npm run dev:server
   ```

2. 対象のファイルを開き、Local Bridge を起動して開いたままにする。
   Dev Mode ではプラグインの一覧に出ないので、Dev Mode をオフにしてから起動する。
   書き換えを頼むなら、そのファイルを編集できる権限が要る。閲覧だけのファイルは複製して編集できるファイルにしてから使う。
   Local Bridge は 1 つのファイルでだけ開く。
   2 つ以上のファイルで開くと、AI の依頼がどちらのファイルに届くか決まらない。
   ほかに開いているファイルで Local Bridge の窓が出ていないかを見る。
   元のファイルと複製のような同じ名前のファイルは、同時に開いたまま使わない (AI がファイルの名前で見分けられない)。
3. Local Bridge の画面の「AI に渡す文をコピー」を押し、AI のセッションに貼って、頼みごとを書く。
   何を対象にするかは、ページ・フレーム・コンポーネントの名前で書くか、Figma で選択してから「選択しているもの」と書く。
   書き換えを頼むときは、書き換えるファイルの名前も伝える。
4. 書き換えのときは、AI から最初に、ファイルの名前と Local Bridge が 1 つだけ開いているかを聞かれる。
   AI が終わったと言うまで、そのファイルを手で触らない (理由は下の「守ること」)。
5. 書き換えが終わると、AI が比べた結果 (report) を開くか、場所を伝える。
   見た目の良し悪しを AI は判定しないので、人が report を見て確かめる。

リポジトリが新しくなったときは、clone したディレクトリで次を実行してから使う。

```sh
git pull
npm install
npm run build
```

取り込み直しは要らない。
ただし、前に Dev Loop という名前で取り込んでいたときは、「初めて使うとき」の 3 のとおり Local Bridge を取り込み直す (Dev Loop は名前と場所が変わって使えなくなったので、**開発**の一覧に残っていても使わない)。

## 使い終わったら

1. Local Bridge の画面の「合言葉を作り直す」を押す。
   合言葉は AI に Figma の書き換えを許す鍵で、AI に渡す文に入っている。
   作り直すと、前に渡した合言葉は使えなくなる。
2. dev サーバーを止める (起動した端末で Ctrl+C。Claude Code に起動してもらったなら、そのセッションに止めてもらう)。
   ほかの AI のセッションが同じ dev サーバーを使っていれば、その依頼も止まる。
3. Local Bridge を閉じる。

## report の見方

書き換える前と後を書き出して比べた結果で、既定では `<clone したディレクトリ>/.dev-dump/compare/<前の番号>-<後の番号>/report.html` にできる。

- 上半分は見た目が変わった画像。
  変わった箇所を 1 つずつ切り出し、before・after・差分 (違う画素を赤くしたもの) を横に並べる。
  範囲が広い箇所と 31 箇所目からは切り出さず、全体の画像で見る。
  左の全体図の枠の番号と、切り出しの番号が対応する。
- 下半分は構造 (レイヤー・プロパティ・変数など) の差分。
  同じ中身の変化は「同じ変化が 21 箇所」のようにまとめて先に出し、「場所」を開くとどのノードかが分かる。
  その下にファイルごとの差分を並べる。多いときは畳んである。SVG のコードはいつも畳んである。
  差分がとても大きいときはファイルごとの差分を載せず、`changes.diff` へのリンクだけを出す。

## AI が戻すとき・戻さないとき

AI が自分で戻すのは、script が最後まで動いて結果が返り、比べたら頼まれたとおりになっていないか、意図しない変化があったときだけ。
Figma の取り消し (Cmd+Z と同じ) で 1 手だけ戻し、書き出し直して前と同じに戻ったことも確かめる。

次のときは、AI は戻さずに report を見せて、戻すかどうかを人に聞く。

- script が途中で止まった・結果が返ってこなかった (どこまで書き換えたか AI に分からない)。
- AI の script では説明できない変化がある (同じファイルを誰かが編集しているかもしれない)。
- 書き換えのあとに、ファイルが触られていた。

戻すと決めたら、次の順で戻す。

1. AI が「書き換える前と変わっていない」と言ったときは、Cmd+Z を押さない。
   script が何も変えていなければ、その前にした別の手が戻る。
2. 変わっているときは、Figma で Cmd+Z を 1 回押し、AI に「戻したので書き換える前と比べて」と頼む。
3. AI が比べて前と同じに戻っていないと言ったら、別の手が戻っている。
   Cmd+Shift+Z を 1 回押して取り消しを取り消し、AI と相談する。

AI が取り消しで別の手を戻してしまったときは、「Cmd+Shift+Z を 1 回押して」と頼まれる (Plugin API には取り消しをやり直す手段が無いため)。

## 守ること

- Local Bridge は 1 つのファイルでだけ開く。
- AI が書き換えているあいだ (戻し終えるまで) は、そのファイルを手で触らない。
  AI の取り消しは Cmd+Z と同じで、人が手でした書き換えのほうが新しいと、そちらが先に戻る。
- ほかのプラグイン (Structure Dump を含む) を起動すると Local Bridge は閉じる。終わったら開き直す。
- 書き出しのあいだは、Figma のウィンドウを前に出し、画面をスリープ・ロックさせない。
- 比べた結果のフォルダ (`.dev-dump/compare/` の下) にはファイルを置かない。比べ直すと消える。
- 合言葉があれば、開いているファイルを書き換えも削除もできる。実行を任せる AI にだけ渡し、ファイルに書いて残さない。

## 困ったとき

- **開発**の一覧に Local Bridge が出ない: Dev Mode になっていないかを見る。Dev Mode をオフにする (Shift+D)。
- AI が「Local Bridge が繋がっていない」と言う: Figma で Local Bridge が開いているかを見る。ほかのプラグインを起動すると閉じている。
- 書き出しが進まない: Figma のウィンドウを前に出し、画面のスリープ・ロックを解く。
- Figma が固まった: 重いページを書き出しているあいだは、Figma ごと固まることがある。前に出したまま待つ。
  待っても戻らないときや、AI から「Local Bridge を開き直して」と頼まれたときは、Local Bridge を閉じて開き直す。
- AI が別のファイルの名前を返してくる: Local Bridge が 2 つ以上のファイルで開いている。1 つだけにする。
- `npm run dev:server` が「dev サーバーはもう … で動いている」と出して終わる: ほかのセッションが起動した dev サーバーが動いている。止めずに、そのまま使う。
- ほかのメッセージが出たときは、そのメッセージを AI に貼って聞く。

## AI が確かめていないもの

- 書き出した範囲の外の変化。AI は書き換えるノードの周りだけを書き出して比べる。
- 非表示のノードは書き出しに映らない。AI は script の返り値で確かめる。
- 別のアカウントが同じファイルを同時に編集しているときに、AI の取り消しがその人の編集を戻さないか (未確認)。
