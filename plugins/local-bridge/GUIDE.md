# Local Bridge 利用ガイド

Local Bridge を使うデザイナーや担当者が、最初に読む文書。
何ができるか、初めて使うときの準備、2 回目以降の使い方、困ったときの対処は、このページだけで追える。
細かい仕様は [README](README.md)、AI が Figma を書き換えるときの手順は [書き換えの手順](../../.claude/skills/figma-safe-edit/SKILL.md) にあり、AI はどちらも読んで動く。
人が読む必要はない。

## 何ができるか

Local Bridge は手元の Figma を AI (Claude Code など) に読み書きさせるためのプラグイン。

- 読む: 画面やコンポーネントの構造と画像を AI に読ませる (実装の参考にする・仕様を書き出す)。
- 調べる: 名前の揺れ・綴り違い・どこにもつながっていない property などを、AI にファイル全体から探させる。
- 開く: 「Button のテーブルを開いて」のように頼むと、AI が Figma を前に出し、そのページに移ってノードを選択した状態にする (リンクをクリックしたのと同じ動き)。
- 書き換える: 組み合わせ表を並べる・名前や色をまとめて直す、など。レイヤーを消すこともできる。
  AI は書き換える前と後を書き出して比べ、結果 (report) を見せる。
  意図しない変化があれば、Figma の取り消し (Cmd+Z と同じ) で戻す。

Figma の公式 MCP と違って回数の上限が無いので、書き出して見比べる往復を何度でも回せる。
Figma のログインや MCP の認証は要らない。

## 用意するもの

- Figma デスクトップアプリ (開発中のプラグインを取り込めるのはデスクトップアプリだけ)。
  入っていなければ https://www.figma.com/downloads/ から入れる。
- Node 22.18 以上 (23 系なら 23.6 以上)。
  入っていなければ https://nodejs.org/ から入れる。
- git
- Claude Code など、手元でコマンドを実行できる AI。
  Claude Code は https://code.claude.com/docs/ja/overview から入れる。

下のコマンドは Claude Code に「このコマンドを実行して」と頼んでもよい。

## 初めて使うとき

1. リポジトリを clone する。
   置いた場所は Figma に取り込んだあと動かさない (Figma は取り込んだ場所のファイルを毎回読み直すので、動かすとプラグインが動かなくなる)。

   ```sh
   git clone https://github.com/simiraaaa/figma-plugins.git
   ```

2. clone したディレクトリで build する。

   ```sh
   npm install
   npm run build
   ```

3. Figma で、どれかのデザインファイルを開く。
   Dev Mode になっていたら、ツールバーの切り替え (Shift+D) で Dev Mode をオフにする (Local Bridge は Dev Mode では使えない)。
   **プラグイン** → **開発** → **マニフェストからプラグインをインポート…** を選び、clone したディレクトリの `plugins/local-bridge/manifest.json` を選ぶ。

取り込みは 1 回だけでよい。
以降はどのファイルでも **プラグイン** → **開発** → **Local Bridge** から起動できる。

## 使うたびに

1. clone したディレクトリで dev サーバーを起動し、動かしたままにする。
   Claude Code に「dev サーバーを background で起動して」と頼んでもよい。

   ```sh
   npm run dev:server
   ```

2. 対象のファイルを開き、Local Bridge を起動して開いたままにする。
   Dev Mode ではプラグインの一覧に出ないので、Dev Mode をオフにしてから起動する。
   書き換えを頼むなら、そのファイルを編集できる権限が要る。閲覧だけのファイルは複製して編集できるファイルにしてから使う。
   複数のファイル (案件) を並べて使うときは、ファイルのタブごとに Local Bridge を開く。
   表示していない裏のタブの Local Bridge も動き続ける。
   同じファイルを分割表示や別のタブで 2 つ開いて両方で Local Bridge を開いても、先に開いた画面の Local Bridge だけが依頼を受け、あとから開いたほうは「止まった」と出て止まる (下の「守ること」)。
3. Local Bridge の画面の「AI に渡す文をコピー」を押し、AI のセッションに貼って、頼みごとを書く。
   渡す文にはそのタブのファイルの名前と、そのファイル専用の合言葉が入っていて、AI はそのファイルにだけ依頼を送る。
   複数のファイルで使うときは、それぞれのタブで渡す文をコピーし、そのファイルを任せる AI のセッションに貼る。
   1 つのセッションに複数のファイルを任せるなら、ファイルごとの文を全部貼る。
   Figma のファイルのリンクだけを AI に貼ると、AI は行き先のファイルは分かるが、合言葉が無いので書き出ししかできない (書き換えも、読み取りだけの script も実行できない)。
   リンクに `/branch/` が入っている (ブランチのファイルの) ときは、AI がどこに送るかを聞いてくるので、そのタブでコピーした渡す文を貼る。
   何を対象にするかは、ページ・フレーム・コンポーネントの名前で書くか、Figma で選択してから「選択しているもの」と書く。
4. 書き換えのときは、AI から最初に、書き換えるファイルの名前を確かめられる。
   AI が終わったと言うまで、そのファイルを手で触らない (理由は下の「守ること」)。
5. 書き換えが終わると、AI が比べた結果 (report) を開くか、場所を伝える。
   見た目の良し悪しを AI は判定しないので、人が report を見て確かめる。

リポジトリが新しくなったときは、clone したディレクトリで次を実行してから使う。
新しくなったかは、dev サーバーが起動したときと 6 時間ごとに確かめ、あれば dev サーバーの端末と Local Bridge の画面に「リポジトリに新しい版がある」と出す。

```sh
git pull
npm install
npm run build
```

実行したら、dev サーバーを止めて起動し直す。

取り込み直しはふつうは要らない。
Local Bridge の画面に「このファイルの fileKey が取れない」と出たときは、「初めて使うとき」の 3 のとおり Local Bridge を取り込み直してから開き直す。
Local Bridge の画面に「この画面の sessionId が取れない」と出たときは、Local Bridge を閉じて開き直す。
それでも出るなら、同じ手順で取り込み直す。
AI に「dev サーバーが古い版」と言われたら、ほかの AI のセッションが dev サーバーを使っていないかを確かめてから、止めて起動し直す。

## 使い終わったら

1. どれかのタブの Local Bridge の画面で「合言葉を作り直す」を押す。
   合言葉は AI に Figma の書き換えを許す鍵で、ファイルごとにあり、AI に渡す文に入っている。
   作り直すと、すべてのファイルの前に渡した合言葉が使えなくなる (ほかのタブでも、もう一度コピーするまで使えない)。
2. dev サーバーを止める。
   起動した端末で Ctrl+C を押す。
   Claude Code に起動してもらったなら、そのセッションに止めてもらう。
   ほかの AI のセッションが同じ dev サーバーを使っていれば、その依頼も止まる。
3. Local Bridge を閉じる (複数のファイルで開いていれば、どのタブでも閉じる)。

## report の見方

書き換える前と後を書き出して比べた結果で、既定では `<clone したディレクトリ>/.dev-dump/compare/<前の番号>-<後の番号>/report.html` にできる。

- 先頭は書き出した範囲の外の変化。
  書き出した範囲の外で変わったノード (script が意図しない場所を変えたか、書き換えの影響が隣に及んだもの) を一番上に、次にインスタンスに映ったものを並べる。
  ノードごとに何が変わったか (位置・大きさ、文字など) の札が付く。
  範囲の外の変化があるときは、その上に「AI の見立て」が出る。
  何がどう変わったか・原因・他の人の変更の疑いを AI が読んで書いたもので、まずこれを読む。
  範囲の中の変化は意図したものなので、ここには出さず、下の画像と構造の差分で見る。
  範囲の外が 1 つでもあれば、見出しが「書き出した範囲の外が変わっている」になる。
  AI が全体スナップショットを取っていないときは、範囲の外は見ていないと出る。
- 次は見た目が変わった画像。
  変わった箇所を 1 つずつ切り出し、before・after・差分 (違う画素を赤くしたもの) を横に並べる。
  範囲が広い箇所と 31 箇所目からは切り出さず、全体の画像で見る。
  左の全体図の枠の番号と、切り出しの番号が対応する。
- 画像の名前とノードの横の「Figma で開く」を押すと、Figma がそのノードを選択した状態で前に出る。
- 最後は構造 (レイヤー・プロパティ・変数など) の差分。
  同じ中身の変化は「同じ変化が 21 箇所」のようにまとめて先に出し、「場所」を開くとどのノードかが分かる。
  その下にファイルごとの差分を並べる。多いときは畳んである。SVG のコードはいつも畳んである。
  差分がとても大きいときはファイルごとの差分を載せず、`changes.diff` へのリンクだけを出す。

## AI が戻すとき・戻さないとき

AI が自分で戻すのは、比べたら頼まれたとおりになっていないか、意図しない変化があったとき (ノードを変えなかった script の印だけの手を片付けるときを含む)。
AI は書き換えの script に自分の印を入れておき、戻すときは Figma の取り消し (Cmd+Z と同じ) を印が消えるまで繰り返す。
script が途中で止まって結果が返らなかったときも、印が残っていれば同じように戻せる (印は書き換えより先に入るので、書きかけでも印まで)。
report の「Figma で開く」で飛んだあとでも戻せる (飛んだ分も一緒に戻るので、見ていたページと選択は書き換える前の位置に戻る)。
戻したあとはファイル全体 (全体スナップショットを取れなかったときは書き出した範囲だけ) を書き換える前と比べ、違いが残っていれば「誰かの編集があるかも」と、変わった場所を添えて伝える。

次のときは、AI は戻さずに report を見せて、戻すかどうかを人に聞く。

- AI の script では説明できない変化がある (同じファイルを誰かが編集しているかもしれない)。
- 書き換えのあとに、ファイルが触られていた。

AI が「印まで戻せなかった」「印を付けずに書き換えた」と言ったときは、人が戻す。

Cmd+Z と Cmd+Shift+Z は前に出ている画面 (タブ・分割表示の片側) のファイルに効き、取り消しの履歴は画面ごとにある。
押す前に、書き換えたファイルの、Local Bridge が依頼を受けている画面を前に出す (別のファイルや別の画面だと、別の手を戻してしまう)。
AI も、押してほしいときはファイルの名前を添えて「そのファイルの画面を前に出してから押して」と頼む。

1. AI に頼まれるまで Cmd+Z を押さない。
   AI は書き換えの script に入れた印を読んで、戻す手があるかを決める (印が無ければ、押すとその前にした別の手が戻る)。
2. AI に Cmd+Z を頼まれたら、そのファイルのタブを前に出して 1 回押し、AI に「押した」と伝える。
   AI が印を読み、残っていればもう 1 回頼む。消えたら AI が書き換える前と比べる (印が無い書き換えのときだけ、AI が言った場所が元に戻るまで押す)。
3. AI が比べて前と同じに戻っていないと言ったら、それ以上押さず、押した回数を AI に伝えて相談する。
   Cmd+Shift+Z は 1 回で 1 手だけやり直すので、押す前の状態に戻すなら、そのファイルのタブを前に出したまま Cmd+Z を押した回数と同じだけ押す (Plugin API には取り消しをやり直す手段が無い)。

## 守ること

- AI に「どのファイルに送るか」を聞かれたら、人が選んで答える。
- 同じファイルを分割表示や別のタブで 2 つ開いて両方で Local Bridge を開くと、先に開いた画面の Local Bridge だけが依頼を受け、あとから開いたほうは断られて止まる (同じ画面で Local Bridge を開き直したときと、ホットリロードのときは、そのまま引き継ぐ)。
  止まったほうの画面では「AI に渡す文をコピー」と「合言葉を作り直す」は押せない。依頼を受けている画面でコピーする。
  取り消し (Cmd+Z・Cmd+Shift+Z) は依頼を受けている画面で押す。
- 10 分を超える書き出しや書き換えの最中に、同じファイルを別の画面 (分割表示・別のタブ) で開いて Local Bridge を開かない。
  10 分を過ぎると別の画面が依頼を引き継ぎ、まだ動いている処理と重なることがある。
- AI が書き換えているあいだ (戻し終えるまで) は、そのファイルを手で書き換えない (ページの移動・選択・report のリンクで飛ぶのは構わない)。
  AI の取り消しは Cmd+Z と同じで、人が手でした書き換えのほうが新しいと、そちらが先に戻る。
- Local Bridge を開いたタブでほかのプラグイン (Structure Dump を含む) を起動すると、そのタブの Local Bridge は閉じる。終わったら開き直す。
- 書き出しのあいだは、Figma のウィンドウを前に出し、画面をスリープ・ロックさせない。
- 比べた結果のフォルダ (`.dev-dump/compare/` の下) にはファイルを置かない。比べ直すと消える。
- 合言葉があれば、そのファイルの書き換えも削除もできる。実行を任せる AI にだけ渡し、ファイルに書いて残さない。
  合言葉がファイルごとなのは、AI が送り先を取り違えたときに止めるため。
  合言葉を渡した AI がわざと別のファイルの合言葉を読み出す script を書けば、別のファイルにも手が届く (仕組みでは防げない)。
  信用できない AI にはどのファイルの合言葉も渡さない。

## 困ったとき

- **開発**の一覧に Local Bridge が出ない: Dev Mode になっていないかを見る。Dev Mode をオフにする (Shift+D)。
- AI が「Local Bridge が繋がっていない」と言う: 頼んだファイルのタブで Local Bridge が開いているかを見る。そのタブでほかのプラグインを起動すると閉じている。
- AI から、Local Bridge が開いているファイルの一覧を見せられ、どれに送るかを聞かれる: AI に渡した文やリンクのファイルで Local Bridge が開いていない。
  そのファイルで Local Bridge を開くか、一覧から送り先のファイルを選んで答える。
  同じ名前のファイル (元のファイルと複製など) が並ぶときは、一覧の fileKey とファイルのリンクの `figma.com/design/` の後ろの文字列を見比べて選ぶ。
- Local Bridge の画面に「このファイルの fileKey が取れない」と出る: 「使うたびに」の最後のとおり、Local Bridge を取り込み直してから開き直す。
- Local Bridge の画面に「止まった (このファイルは別の画面で Local Bridge が開いている)」と出る: 同じファイルを分割表示や別のタブでも開き、先にそちらで Local Bridge を開いていた。こちらを使うなら、もう片方の Local Bridge を閉じ、35 秒ほど待ってから、こちらを閉じて開き直す (すぐ開き直すと、まだ断られる)。
  もう片方の画面が書き出しや書き換えの途中で閉じられていたときは、10 分ほど断られ続ける。急ぐなら、もう片方の画面で Local Bridge を開き直す。
- Local Bridge の画面に「止まった (この画面で Local Bridge が走り直した)」と出る: 同じ画面の新しい Local Bridge が依頼を受けている。止まったほうの窓は閉じてよい。
- Local Bridge の画面に「古い版の dev サーバー」と出る: ほかの AI のセッションが dev サーバーを使っていないかを確かめてから、止めて `npm run dev:server` で起動し直す。
- AI が「合言葉がまだ無い」「合言葉が違う」と言う: 別のタブで合言葉を作り直したか、別のファイルの渡す文を渡している。書き換えたいファイルのタブで「AI に渡す文をコピー」を押し、貼り直す。
- 書き出しが進まない: Figma のウィンドウを前に出し、画面のスリープ・ロックを解く。
- Figma が固まった: 重いページを書き出しているあいだは、Figma ごと固まることがある。前に出したまま待つ。
  待っても戻らないときや、AI から「Local Bridge を開き直して」と頼まれたときは、Local Bridge を閉じて開き直す。
- `npm run dev:server` が「dev サーバーはもう … で動いている」と出して終わる: ほかのセッションが起動した dev サーバーが動いている。止めずに、そのまま使う。
- ほかのメッセージが出たときは、そのメッセージを AI に貼って聞く。

## AI が確かめていないもの

- 書き出した範囲の外の変化のうち、全体スナップショット (ファイル全体のノードごとの名前・位置・大きさ・塗り・文字などの要約) に入らない値。
  AI は書き換えるノードの周りだけを書き出して比べ、範囲の外は全体スナップショットの前後を比べて、変わったノードの id を見つける (report の先頭に出る)。
  全体スナップショットに入らない値 (書き出し設定・プラグインのデータなど) の変化は拾えない。
- 非表示のノードは書き出しに映らない。AI は script の返り値で確かめる。
- 別のアカウントが同じファイルを同時に編集しているときに、AI の取り消しがその人の編集を戻さないか (未確認)。
